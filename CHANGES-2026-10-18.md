# Changes 2026-10-18: Encircle link

## What it does

When a JobTread job reaches an awarded status (Bid Accepted, Upcoming To Be Scheduled, Scheduling required, Scheduled (Date promised), Turnover Meeting Required, NOP or Site work), the app makes the matching job in Encircle. Then it posts one pinned comment on the JobTread job with the Encircle link. Only staff see that comment.

The link between the two is our JobTread job number, saved in Encircle as the contractor identifier. No JobTread field is used, because jobs already hold the 25-field limit. Photos stay in Encircle only.

The Sites screen gets a new card, Site photos in Encircle. It shows each job on site with its photo count, and lists anything that needs a person. It also adds an alert when a job is on site with no photos.

## Uses the app's own JobTread key

Encircle uses the key already saved in Settings, JobTread. There is no second copy. JOBTREAD_GRANT_KEY in Netlify only overrides it, and is not needed.

## Netlify settings

Already in (2026-10-18): ENCIRCLE_TOKEN (secret), ENCIRCLE_ORG_ID, ENCIRCLE_BRAND_ID, ENCIRCLE_MODE = off.

Still to add:
- ENCIRCLE_HOOK_KEY: a random string of at least 32 characters, marked secret. It proves a webhook call came from JobTread.
- ENCIRCLE_START_DATE: the go-live date as YYYY-MM-DD. Only needed for live.

ENCIRCLE_MODE:
- off: does nothing. The card says so.
- test: only TEST job 99-00001 is touched. Its Encircle job is named "TEST - ..." so nobody mistakes it.
- live: real jobs. Only jobs opened on or after ENCIRCLE_START_DATE get a new Encircle job. Older awarded jobs go on the Needs a person list, because many likely already have an Encircle job made by hand without our job number. Type the job number into that Encircle job's contractor identifier and the next morning check links it.

## Safety

It stops rather than guess when:
- Encircle already has two jobs with the same number.
- Encircle's search returns jobs that are not the one asked for (the filter is not working, so creating would risk a duplicate).
- The JobTread job has no site address or client.
- JobTread returns fewer jobs than it says it has.

Two runs at the same moment could both create a job. It checks straight after creating and says so if that happened.

## Deploy and test, in order

1. Merge this branch and deploy. ENCIRCLE_MODE stays off. Check the Sites screen shows "The Encircle link is switched off."
2. Add ENCIRCLE_HOOK_KEY in Netlify and redeploy.
3. The JobTread key in Settings, JobTread must be from an A&M account, with "updateOrganization" allowed. Then, on a computer with Node, from the tools folder:
   `$env:JOBTREAD_GRANT_KEY="..."; $env:ENCIRCLE_HOOK_KEY="..."; node register-jobtread-webhook.mjs`
   Never paste either key into a chat or email.
4. Set ENCIRCLE_MODE to test and redeploy.
5. Move TEST job 99-00001 to Bid Accepted. Within a minute: a "TEST - Aldergrove Builders Inc." job appears in Encircle, and a pinned Encircle comment appears on the JobTread job.
6. Move the TEST job back to New Lead, then to Bid Accepted again. No second Encircle job appears and no second comment.
7. Add one photo to the TEST job in Encircle. The next morning check shows it on Sites (set the TEST job to Site work to see it in the list).
8. Set ENCIRCLE_START_DATE and ENCIRCLE_MODE to live, and redeploy. Work through Needs a person from the first live morning check.
9. Delete the TEST job in Encircle when done, or leave it for the next test.

## Run the checks

`npm install`, then `node test/encircle.test.mjs` and `node test/encircle-app.test.mjs`.
