# Inventory app changes - 2026-10-06 (v42)

For Bruce. Deploy this over v41. Nothing in the data needs converting.

## Before you deploy: set these in Netlify

Site configuration, then Environment variables. Then redeploy.

| Name | What to put | Why |
|---|---|---|
| `AUTH_SECRET` | A long random string (40+ characters). Generate one, never reuse. | The key that signs everyone in. Without it the key sits in the data store. Setting it signs everyone out once. |
| `OFFICE_USERS` | Names exactly as they appear in the app, comma separated. For example `Jen Garrison,Craig Williams,Max` | Only these people can change people, PINs, settings, the JobTread and QuickBooks connections, or wipe history. If it is empty, everyone is treated as office, as before. |
| `FEED_TOKEN` | Another long random string (at least 24 characters). | Turns on the read-only summary at `/api/feed`. Leave it unset to keep the feed off. |
| `TOKEN_DAYS` | Optional. Default 30. | How long a phone stays signed in before it needs the PIN again with signal. |
| `JT_PUSH_ENABLED` | Leave unset. | Sending cost to JobTread stays off until it is rebuilt and tested on a practice job. |

## After you deploy

1. Make sure at least one person has a PIN. The sign-in gate now stays on for good once it has been on.
2. Open the office settings and reconnect QuickBooks with the new Connect button (the old link no longer works).
3. Have Jen add a test person, issue a PIN, and sign in on a phone that has never had the app. Their name should be on the sign-in list straight away.

## What changed

### Jen's fault: new members cannot sign in, "data not found"
- The sign-in screen now gets the list of names from the office (`GET /api/auth`, names and has-PIN only), not from the phone's own old copy.
- A phone that is refused no longer treats that as "the office has nothing" and no longer tries to make the starter file the company's list.
- Whether sign-in is needed is remembered from the office, so an old phone cannot decide nobody has a PIN.
- Straight after signing in, the phone syncs and replaces the starter list with the real one instead of merging the two.
- Saves that are not allowed or not possible now say why in plain words instead of failing silently or showing "auth".
- Removing a person now sticks on every phone.

### Security
- The sign-in gate cannot switch itself off again once anybody has had a PIN.
- Office-only actions are checked on the server (see `OFFICE_USERS`). A crew phone can no longer set anyone's PIN, switch people off, change settings, change the JobTread key, link or bill in JobTread, connect or disconnect QuickBooks, or wipe history.
- QuickBooks connect needs an office sign-in. The one-time code expires after ten minutes and works once.
- Sign-in tokens expire (30 days by default) and are no longer accepted in the web address.
- Wrong PINs are counted so a burst of guesses cannot slip past, plus a second limit per connection (30 wrong in an hour).
- Any old JobTread key left in the catalog settings is stripped before the catalog goes to phones.
- The server records who was signed in when each movement arrived (`sentBy`), alongside the name the phone wrote.

### Data safety
- Movements from two phones arriving at the same moment can no longer overwrite each other. Pushes now take a short lock.
- Two catalog saves at the same moment can no longer both win. One is told to retry.
- Needs `@netlify/blobs` 10 (package.json updated) for the conditional writes.
- A save that has to be retried no longer downloads the whole movement history.
- The sync position is compared as a number, so phones stop re-pulling the same movements.

### Other fixes
- Five "today" checks used the UTC date, so they went wrong after about 6 pm in Edmonton. Fixed.
- Matching an inventory job to JobTread can now search every JobTread job by number or name, not just the newest 25.
- The JobTread link check now fails safe: if it cannot check, it does not write.
- QuickBooks vendor list raised from 200 to 1,000.
- New: `GET /api/feed` read-only summary for the command centre (shelf stock, low stock, machines and material out per job with the JobTread id, gear on closed jobs, missing machines). Off until `FEED_TOKEN` is set.

## Still open
- Sending material cost to JobTread (`pushCost`) needs rebuilding so the lines are worked out on the server from the movement log, plus a map from shelf items to JobTread cost codes. Then a test on a practice job.
- Kits are still empty and still block Close job if a kit tag is scanned out.
- PINs are still 4 digits hashed once on the phone. The counters make guessing slow; a longer PIN would be better.
